# Getting help

This page explains where to go with a question, a problem or an idea about a Buildruntime project. It applies to every repository under [buildruntime](https://github.com/buildruntime) that does not have its own `SUPPORT.md`.

## Before you ask

Many questions are already answered. Check these first:

1. The **README** and any documentation in the repository concerned.
2. The repository's **issues**, open and closed. Search for the error message or the feature you are interested in.
3. The **changelog** or **releases** page, if the problem started after an upgrade.

## Where to go

| You want to | Go to |
| :-- | :-- |
| Report a security vulnerability | Follow the [security policy](https://github.com/buildruntime/.github/blob/main/SECURITY.md). Never post vulnerability details in public. |
| Report a bug | Open an issue in the affected repository and choose **Bug report**. |
| Suggest a feature or a change | Open an issue in the repository concerned and choose **Feature request**. |
| Ask a question about using a project | Open a blank issue in the repository concerned. Start the title with "Question:". |
| Report behaviour that breaks the Code of Conduct | Follow [How to report](https://github.com/buildruntime/.github/blob/main/CODE_OF_CONDUCT.md#how-to-report) in the Code of Conduct. |
| Contribute a change | Read the [contributing guide](https://github.com/buildruntime/.github/blob/main/CONTRIBUTING.md). |
| Contact the maintainers about something that should not be public | Email [manav.it3101@gmail.com](mailto:manav.it3101@gmail.com). |

## Contact

The Buildruntime contact address is [manav.it3101@gmail.com](mailto:manav.it3101@gmail.com). Use it for matters that cannot be raised in a public issue, such as a conduct concern, or a question that involves private information.

Ask questions, and report bugs and feature requests, in issues, where the answer can also help other people. Requests of that kind sent by email will be redirected to issues. Report security vulnerabilities as described in the [security policy](https://github.com/buildruntime/.github/blob/main/SECURITY.md), which prefers GitHub's private vulnerability reporting to email.

There is no chat server, mailing list or phone support.

## Asking a good question

A question that can be answered without a round of follow-up questions gets answered sooner. Include:

- what you are trying to achieve, not only the step that is failing;
- what you have already tried, and what happened;
- the version of the project you are using, and the relevant parts of your environment, such as operating system and runtime version;
- the smallest example of code or configuration that shows the problem, as text rather than a screenshot.

Remove passwords, tokens, private keys and personal data from anything you paste.

## What to expect

Buildruntime projects are maintained alongside other work, and support is given on a best-effort basis. Maintainers respond as their availability allows, so we cannot promise a response time or a fix by a particular date.

We can help with using a project, and with problems in the project itself. We cannot help with general programming questions, or with problems in your own code or in third-party software that is not caused by a Buildruntime project.

If an issue has gone quiet, add any new information you have rather than a comment asking for an update. An issue that has waited a long time for information from the reporter may be closed, and can be reopened when the information is available.
